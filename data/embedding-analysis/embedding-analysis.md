# Embedding Space Analysis

## Overview

Qdrant に格納した 1,000 コースの dense embedding (OpenAI text-embedding-3-small, 1536-dim) を t-SNE で 2D に射影し、4 つの軸で色分けして分布を分析した。

embedding がデータの何を捉え、何を捉えていないかを明らかにし、RAG 設計の妥当性を検証する。

## Findings

### 1. Level does NOT form clusters

Beginner (547), Intermediate (308), Advanced (32) が空間全体に均一に混在。レベルによるクラスタは形成されていない。

**理由**: embedding は「コース内容の意味的類似性」を捉えており、レベル（難易度）は意味空間の軸ではない。「Beginner Python」と「Advanced Python」は内容が近いため、embedding 空間でも近傍に配置される。

### 2. Organization does NOT form clusters

提供組織ごとの色も空間全体に分散。同じ大学のコースでも、トピックが違えば離れた位置に配置される。

### 3. Skill shows weak clustering

上位 15 スキルで色分けすると、部分的な集まりは見えるが Topic ほど明確ではない。805/1000 が "Other" に分類されており、skills データ自体が sparse（2,195 ユニークスキル、平均 3.5/コース）であることが原因。

### 4. Topic DOES form clear clusters

Topic（ML/AI, Data Science, Cloud/DevOps, Business, Cybersecurity 等）で色分けすると、**同じトピックのコースが明確にクラスタを形成**している。

これにより、embedding が捉えているのは**トピック（科目分野）の意味的類似性**であることが確認できた。

## What embedding captures vs. what it does NOT

| Dimension | Captured by embedding? | Evidence | RAG での扱い |
|-----------|----------------------|----------|-------------|
| **Topic / Subject area** | ✅ Yes | t-SNE でクラスタ形成 | Semantic search（dense vector） |
| **Specific skills** | △ Partially | Sparse data、弱いクラスタ | BM25 keyword matching で補完 |
| **Difficulty level** | ❌ No | 空間全体に混在 | Qdrant payload filter |
| **Provider organization** | ❌ No | 空間全体に分散 | Qdrant payload filter |
| **Rating** | ❌ No | 数値メタデータ | Qdrant payload filter |

この表が示すのは、**embedding は「何についてのコースか」を捉えるが、「誰が提供し、どのレベルで、どう評価されているか」は捉えない**ということ。これは text-embedding-3-small が意味的類似性に最適化されたモデルであることと整合する。

## Implications for RAG Design

### Validated Design Decisions

| 設計判断 | 根拠 |
|---------|------|
| **Level は payload filter で処理** | embedding 空間で分離しないため、Qdrant の payload filter (`level` field) で絞り込むのが正しい |
| **Semantic search はトピック類似度に専念** | embedding がトピックを正確にクラスタリングしているため、クエリの意図に合ったコースを retrieve できる |
| **Hybrid search (BM25 + dense + RRF) は妥当** | トピッククラスタ内の細かい区別（特定スキル、特定ツール名）は BM25 の keyword matching が補完する |

### Current Implementation (validated)

```python
# hybrid_search.py — Level is a filter, NOT part of embedding query
qdrant_filter = _build_filter(level, min_rating, organization)

# Agent prompt — Level extracted as filter parameter
# "beginner courses" → level="Beginner", query passed separately
```

この設計は embedding 空間の特性と整合しており、**変更の必要はない**。

## Topic Classification: Current Approach and Future Directions

### Current: Rule-based keyword matching

コースタイトルからキーワードマッチで 10 カテゴリに分類。分類率 35.6%（644/1000 が "Other"）。

これは分析用の簡易分類であり、検証目的には十分だが、プロダクション用途には精度が不足する。

### Future: Embedding-driven topic discovery

embedding 空間にクラスタが存在することが確認できたため、**embedding 自身にトピックを語らせる** アプローチが有望。

| 手法 | 精度 | コスト | 特徴 |
|------|-----|-------|------|
| **キーワードマッチ（現状）** | 低（36%分類） | $0 | ルール追加で改善可能だが限界あり |
| **LLM 分類** | 高 | ~$0.05/1000件 | GPT-4o-mini でタイトル→カテゴリ。高精度だが API 依存 |
| **Embedding クラスタリング (HDBSCAN)** | 中〜高 | $0 | t-SNE で目視確認済みのクラスタを自動検出。代表コースからトピック名を付与 |
| **BERTopic** | 高 | $0 | embedding + HDBSCAN + c-TF-IDF でトピック自動抽出。トピック名も自動生成 |

**Embedding クラスタリング** は特に注目に値する。今回の分析で以下が確認できた：

1. t-SNE 上でクラスタの存在を目視確認 → HDBSCAN 等で自動検出が可能
2. クラスタの中心にあるコースを見れば、トピック名を推定できる
3. 外部 API 不要（embedding は既に Qdrant に格納済み）

これは単なるラベル付けではなく、**データセットのカバレッジ分析**（どの分野のコースが多い/少ないか）や**RAG のギャップ検出**（ユーザーのクエリ分布と比較して、コースが不足している領域の特定）にも応用できる。

## Notes

- "Other" in Topic (644/1000): keyword-based classification の限界。hover でコース名を確認すると、health, design, math, music 等の未分類トピックが含まれる。
- "Other" in Skill (805/1000): skills データが sparse（2,195 ユニーク、多くのコースでスキル未登録）。
- t-SNE の軸 (t-SNE 1, t-SNE 2) 自体に意味はない。相対的な距離関係のみが解釈可能。
